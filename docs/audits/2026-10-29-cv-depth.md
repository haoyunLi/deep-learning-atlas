Scope: scanned the full 233-lesson catalogue for overlap, then reviewed the 29 `vision` lessons and the related DINO/assignment/representation lessons. Six new lessons deepen operational gaps; they do not claim to replace all architecture introductions. ### 1. `faster-rcnn-yolo` — distinguish original RoI Pooling from later implementations

Current exact `core`:

> backbone/FPN 产生多尺度特征。Faster R-CNN 的 RPN 生成 proposals，经 RoIAlign 得定长特征后分类回归；YOLO 类 head 在多尺度位置直接输出 objectness/class/box。训练依赖匹配规则，推理通常还需阈值和 NMS。

Suggested exact replacement:

> Backbone 提取特征，现代配置常接 FPN。Faster R-CNN 的 RPN 生成 proposals；原版使用 RoI Pooling，现代实现可用 RoIAlign 提取定长区域特征，再分类与回归。YOLO 是一组 one-stage detection 方法，不同版本的 anchor、objectness、head、matching 与后处理不同，需按选定实现核对。训练依赖目标分配与损失，推理是否需要 NMS 也应按版本确认。

Reason: the current text silently attributes RoIAlign to the original Faster R-CNN and treats one YOLO output contract as universal. [Faster R-CNN original](https://arxiv.org/abs/1506.01497), [Mask R-CNN: RoIAlign section](https://arxiv.org/html/1703.06870v3), [Ultralytics YOLOv8: anchor-free split head](https://docs.ultralytics.com/models/yolov8/). Source versions refer to those methods; no claim about the newest/best model is needed.

### 2. `cnn` and `vgg` — theoretical and Effective Receptive Field are distinct

In `cnn.core`, replace the exact sentence:

> 堆叠层会扩大有效感受野，形成从边缘、纹理到物体部件的层级。

with:

> 堆叠层通常扩大 theoretical receptive field，形成从边缘、纹理到物体部件的层级；Effective Receptive Field 指实际影响分布，取决于权重、非线性与输入，不等于理论覆盖区域。

In `vgg.equation`, replace:

> Fₗ₊₁ = ReLU(Conv₃×₃(Fₗ)); 多层堆叠扩大有效感受野

with:

> Fₗ₊₁ = ReLU(Conv₃×₃(Fₗ)); 多层堆叠扩大 theoretical receptive field，实际影响分布需另看 Effective Receptive Field

[Effective Receptive Field paper](https://arxiv.org/abs/1701.04128). New FPN lesson provides the explicit jump/radius arithmetic, so old introductions can link there without duplicating the derivation.

### 3. `vit` — changing patch size changes the model contract

Current `patch size P` setting `adjust`:

> 小目标被整块吞没可比较更小 P；显存超限则增 P 或改 Swin。

Suggested replacement:

> 小目标被整块混合时，先比较同 checkpoint 更高输入分辨率或局部 refinement；若比较更小 P，应选配套架构/checkpoint或明确重新适配 PatchEmbed，不能只改 P 数字复用原权重。显存超限则降低输入 token 数或比较 Swin。

The current wording could imply that patch size is an inference knob on arbitrary pretrained weights. [DINOv2 official token/patch implementation](https://github.com/facebookresearch/dinov2/blob/main/dinov2/models/vision_transformer.py) and the new dense-feature lesson make the distinction explicit. The same principle applies to ViT generally, with checkpoint-specific adaptation possible.

## Coverage audit conclusions

- Existing architecture introductions correctly distinguish concatenation in DenseNet/U-Net from addition in ResNet and FPN-like paths. No new architecture-name list was needed.
- Existing SAM course already limits zero-shot generalization and quality scores; new preprocessing lesson adds point/box coordinate contracts.
- Existing Detection Metrics correctly separates NMS from evaluation thresholds. New loss course is deliberately separate so a user can tell preprocessing, assignment, training loss, post-processing and evaluation apart.
- Existing Tracking has a 2×2 greedy counterexample but does not explain solver internals or optional matching. The new lesson adds a 3×3 zero-covering derivation and an independently enumerated optimum.
- Existing DINO explains teacher/student training. Dense matching is a distinct downstream workflow with explicit patch shape and failure cases; it does not claim DINO features automatically register images or segment cells.
- Existing 3D coverage already includes camera geometry, stereo, point clouds and NeRF/3DGS. Keypoint decoding is a more useful immediate gap than adding another reconstruction architecture. Bundle Adjustment, PnP, differentiable rendering and 3D segmentation remain reasonable later extensions, not claimed completed here.
- The 17 short introductory CV lessons can remain accessible entry points, but root should link them to the six new detail lessons so readers can reach concrete settings and diagnostics.

## Checked primary sources and teaching boundaries

- [Torchvision joint transforms](https://docs.pytorch.org/vision/stable/transforms.html): image/box/mask joint transformation; our letterbox/flip numbers are independently authored fixtures.
- [FPN original](https://arxiv.org/abs/1612.03144): top-down/lateral feature architecture; our shapes, bytes and receptive-field calculation are synthetic.
- [GIoU](https://arxiv.org/abs/1902.09630), [DIoU](https://arxiv.org/abs/1911.08287), [Torchvision GIoU loss contract](https://docs.pytorch.org/vision/stable/generated/torchvision.ops.generalized_box_iou_loss.html): equations and valid box conventions. Our coordinate/derivative examples are independently recomputed.
- [DETR matcher](https://github.com/facebookresearch/detr/blob/main/models/matcher.py): class matching cost is `-p`, matching is under `no_grad`; unmatched queries get no-object supervision downstream. [DETR parameters](https://github.com/facebookresearch/detr/blob/main/main.py): matching class/L1/GIoU 1/5/2; box loss L1/GIoU 5/2; these are source settings, not universal recommendations.
- [SciPy assignment](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html): rectangular contract and modified Jonker–Volgenant implementation. The 3×3 example originates here; row/column reduction illustrates classical Hungarian mechanics and is not described as SciPy's exact internal algorithm.
- [DINOv2](https://arxiv.org/abs/2304.07193), [official token outputs](https://github.com/facebookresearch/dinov2/blob/main/dinov2/models/vision_transformer.py): patch/CLS/register separation; similarity arithmetic and match thresholds are synthetic validation exercises, not claimed model results.
- [Integral Human Pose Regression](https://arxiv.org/abs/1711.08229): soft-argmax/integral coordinate decoding. The two-mode mean counterexample and temperature calculation are independent teaching fixtures.

## Validation

`node scripts/validate-cv-depth.mjs` checks all six lessons, twelve exercises, six figures, all compareTo links, and 49 independently calculated numerical assertions. It uses exhaustive permutations as the assignment oracle, finite differences for the separated-box gradient, and explicit probability normalization for soft-argmax. It does not train a model or make a benchmark claim.
